# 摸鱼小李 · 电商图与详情页视觉导演

一个面向豆包主图、副图和详情页生产的电商视觉 skill。既能拆解优秀参考图并迁移到你的产品，也能在详情页只有产品图或零散身份规格时先识别并整体调研，交付卖点信息大纲供你确认，再完成设计大纲、逐屏执行与完整图文生图。

## 这版解决了什么

- 用户明确要 5 张且未另定顺序时，默认采用“封面点击—痛点共鸣—差异卖点—场景价值—CTA 收口”五图骨架；未指定张数时才自适应；
- 不再强制 6–15 屏或固定九屏，按购买问题、证据和平台规则选择最小有效集合；
- 只给产品图，或只有身份/零散规格，且没有完整、已批准、证据合格的本 SKU 卖点集时，不直接猜文案和生图：先调研并交付卖点信息大纲，确认后才进入视觉设计；
- 详情页先交付整套设计大纲，确认屏序、文案素材和视觉系统；再一次完成全部逐屏详细设计执行稿，确认后才进入锚定与批量生图；
- 没有风格参考时，从商品视觉基因检索版式、摄影、品牌与材质灵感；视觉研究与产品事实分账；
- 给每个资产分配 P/B/E/L/T/S/C 角色、授权与传输方式；产品、品牌和真实证据始终是硬约束；
- 反推时先提取参考图的主体层级、版式/留白、光影、材质、色彩和文字融合等承重机制；默认给“忠实迁移、构图升级、场景叙事、信息设计”4 个真正不同的方向，不靠换背景凑变体；
- 整条竞品详情页只分析屏序、版式和节奏；按语义屏提炼 L/T，未授权第三方原图不直通模型；
- 把 prose 母版升级为可版本化 Visual System Contract，styleWeight 与 layoutWeight 独立；
- 先做必要版式/场景锚，再扩展整套，避免包装漂移、参考泄漏和页面像拼盘；
- 多图提示词由 GLOBAL 常量、场景族、单图差量、可见文字和验收五层编译；逻辑 manifest 记录稳定图号、依赖、版本与增量返修；
- 提示词详细到网格、产品占位、前中后景、镜头、布光、色盘、材质、可见文字、信息层级和验收，但不按字数堆废话；
- 主标题、副标题、卖点、标签、参数、营养/配料、表格、FAQ、当前价格和法务全部直接在豆包成图中生成，不再区分“短字直出、长字外排”；
- 优先锁真实产品像素，生成背景、道具和光影融合；局部问题局部修，不整图反复抽奖；
- 价格、活动、赠品、库存、物流等在 SKU、地区、期限和条件明确后也直接生成；后续变更用豆包局部改字或只重生对应图；
- 机器、设计和商业/事实三层验收，并保留 AI 来源、提示词、编辑记录和元数据。

## 两种模式

### 参考图反推迁移

参考图只教构图、镜头、光、色彩、材质和信息层级。第三方产品、品牌、包装、文案、数据和证据不会进入你的成品。生成前需要你的产品信息，最好有正侧背/多角度实拍。默认 4 个方向都必须保住参考图的完成度承重机制；若主体层级、光影、材质、版式或文字融合有两项明显退化，先返修而不是把弱结果当“创意”。

### 从零做主图与详情页

输入产品名称、品类和可信基础资料即可。skill 会：

1. 定义平台、类目、SKU、售卖单位和交付范围；
2. 如果只有产品图/零散身份规格且没有完整合格卖点集，先识别 SKU 并调研同 SKU 官方资料、权威知识、当前平台规则与买家疑问；
3. 先交付`调研卖点信息大纲`：来源、事实、买家问题、候选卖点/证据/限制/四态准入、Top 1–3 信息层级和确认清单；等你确认后再继续；
4. 建立 F/K/Q/E/R/D/U 与 SP 账本，资料完整的任务可直接从这里开始；
5. 明确要 5 张主图时使用 G1–G5 默认叙事；未指定张数时自适应。详情页从 M1–M8 选配，并从视觉基因研究 2–4 个可生产方向；
6. 给整套详情页设计大纲：设计命题、决策叙事、模块取舍、屏序、每屏文案素材/视觉概念、构图/场景族和上下承接；
7. STANDARD 确认设计大纲后锁定 Visual System，一次写完全部逐屏详细设计执行稿；
8. 每屏提示词写到可直接生图：画布、产品、空间、镜头、光色、材质、完整文字排版、连续性、禁项和验收；
9. 统一确认执行包后生成首屏/必要场景族锚，通过 Anchor Checkpoint 再批量；
10. 一图一任务、一屏一图，在豆包一次生成画面与全部已确认文字；OCR/目视校对，错字优先局部改字。

交互节奏分 `STANDARD / FAST / PROMPT_ONLY`。资料完整时，STANDARD 依次确认设计大纲、执行包和锚图；FAST 只省正常等待；PROMPT_ONLY 不制造生图门。但只有产品图/零散身份规格且没有完整合格卖点集时，Research Gate 三种模式都必须由用户确认。

主图与详情页组合任务在 Gate 1 分别记录并同时确认 `mainImageStrategyStatus` 与 `detailOutlineStatus`；任一未通过，不进入共同执行包或共享锚。

### 明确要 5 张主图时

默认次序为：G1 封面首图·点击率担当 → G2 痛点共鸣·用户代入 → G3 差异化卖点·竞品区隔 → G4 场景展示·使用价值 → G5 CTA·行动收口。每张用户可见策略卡只有**画面 / 图内文案 / 设计指引**三项，图内文案最多 5 个可见行，必要限定语也计入。若某一角色与平台、类目或证据冲突，保留 5 张数量，用背标、细节、规格、实收、储运或用法等真实信息替代，不伪造痛点、竞品、资质、价格或按钮。

### 详情页 M1–M8 模块库

- M1 首屏痛点共鸣；M2 核心优势铺开；M3 配方/工艺纵深；M4 使用场景；
- M5 品牌/资质背书（可选）；M6 规格参数+竞品对照；M7 FAQ；M8 购买引导+法务声明（可选）。

模块数不等于屏数：一个 M2 可拆几屏，多个模块也可合并。M7 不是必做；入选时围绕真实疑问约 6 题（默认 5–7），末题必须是产品属性/用途边界与必要声明。设计大纲和逐屏执行卡同样只显示**画面 / 图内文案 / 设计指引**，追溯与生产绑定收进设计指引。

## 只有产品图或零散资料时，先确认什么

第一份交付不是详情页画面，而是`调研卖点信息大纲 vX`：

- 产品身份、SKU/规格/包装版次、识别置信度和调研范围；
- 来源链接或文件、访问日期、同 SKU/地区/时效匹配和冲突；
- 已核验事实、买家高频疑问和候选卖点池；
- 每个 SP-ID 的准确候选文案、消费者价值、事实/证据、限定语、优先级；`evidenceStatus` 表示可直接用/需核实/仅类目教育/禁用，`selectionStatus` 另记待选/采用/修改/拒绝；
- 建议 Top 1–3 主信息、未知/冲突/禁用项和逐项确认清单。

你只需回复采用、修改或不采用哪些 SP-ID，并纠正 SKU/范围、补标签或证据。只有`ELIGIBLE + ADOPTED`可作本品主张；`CATEGORY_ONLY + ADOPTED`仍只能做类目教育，`MODIFIED`要重新核验。确认不会让无证功效、认证、比较、产地或检测数字变成事实。

## 在豆包中使用

优先导入完整 skill 文件夹或 ZIP，保证 `SKILL.md` 能按任务读取对应 `references/`；若所在工作区只能粘贴内容，至少同时提供 `SKILL.md` 和当前模式点名的参考文件。直接说“用这个 skill 为我的产品做主图/详情页”，并上传产品正侧背、包装文字和可用品牌资产。最终 prompt 会把本屏全部已确认文字直接交给豆包生成；成图错字继续在同一会话用局部改字修正。

## 你会得到什么

### Part 0｜调研卖点信息大纲（产品图/零散资料且卖点集不完整时）

先把能讲、待核、只能做类目教育和必须禁用的内容分开，并形成可追溯的 SP-ID 卖点池。此阶段不提前做视觉执行或生图。

### Part A｜详情页设计大纲

先看到整套购买决策和设计系统：项目/事实边界、核心设计命题、Visual System 预设、模块取舍、屏数依据、屏序、每屏买家问题/唯一信息/逐字文案素材/视觉概念/构图族/信息密度/证据/参考/上下承接、场景族与锚定计划，以及未知项。大纲回答“整套为什么这样设计”。

### Part B｜全部逐屏详细设计执行

大纲确认后，每屏只保留三个一级项：

- **画面**：产品位置、尺度、环境、动作、前中后景、镜头、光、色彩、材质、第一落点、动线与语义道具；
- **图内文案**：逐字标题、副标题、标签、参数、表格、FAQ、价格/活动条件与必要限定；每段都标强制换行、文本框、字体类别/气质、字重、相对字号、HEX、对齐、行距、字距、底色对比和与产品关系；
- **设计指引**：购买任务、证据、Visual System/场景族、参考分工、移动端、上下承接、禁止项、验收，以及可直接复制到豆包的完整自足生图执行稿。

全部屏一次写完后统一确认，不逐页询问；每屏同时绑定事实/证据/规则和版本。

### Part C｜生图与验收

每张交付：Visual System 版本、参考资产角色/授权/传输方式、逻辑 job、画布网格、五层源卡、编译后的完整中文提示词、豆包生成/局部改字计划、针对性禁止项和验收标准。提示词不只写“高级、8K”，而是写清：

- 产品几何、包装、标签、颜色、数量、状态；
- 产品/标题/信息区比例与移动端安全区；
- 前景、中景、后景和遮挡/接触关系；
- 镜头高度、俯仰、焦段、焦点和景深；
- 主光、补光、轮廓光、色温、高光与阴影；
- 色盘比例、材质粗糙度、反射/折射、液体/食物/织物状态；
- 每个文字块的逐字原文、强制分行、相对坐标/文本框宽高、最大行数、字体类别与气质、字重、字高占画布比例、HEX、对齐、行距、字距、底色对比、产品避让/咬合关系与 OCR/目视目标；
- 实际参考图逐张点名、长页母本隔离、style/layout 权重和泄漏检查；
- 本张最可能的产品、事实、物理和渠道错误。

## 研究与事实边界

- 产品专属事实只来自你的资料、清晰包装或匹配同 SKU 的官方来源；
- 包装 OCR、瓶型、颜色和文件名先是观察，不因看起来像某个商品就自动成为本 SKU 事实；
- 类目知识只能解释，不证明你的产品具备某成分、工艺或效果；
- 竞品、评论和参考图只帮助发现购买问题与视觉机会；
- 查不到的内容标未知、删屏或请你补关键证据，不编数字、认证或故事；
- 工厂、果园、实验室、专家、证书、报告、专利、评价和销量只使用真实授权素材，AI 不伪造；
- 比较与前后对比默认关闭，证据和比较条件齐全才启用；
- 免责声明不能挽救虚假主张，限制条件与主张邻接。

## 平台适配

张数、比例、首图文字、标签/资质槽位和 AI 声明按“平台×站点×类目×日期”核验。公开规则不足时，明确提示以上架后台为准，不把第三方博客中的尺寸和顺序冒充 2026 通则。跨平台适配会重新排版，不是机械裁切同一张图。

## 你可以直接这样说

- “帮我反推这张主图，用我的产品重做，不抄品牌和文案。”
- “只有包装正反面和基础参数，帮我查资料并补齐主图与详情页。”
- “先给我每张主图的画面、文案和设计指引，确认后再出图。”
- “参考这套果汁详情页的高级感和节奏，但 HPP、100%、工厂等都不是我的资料。”
- “目标是抖音食品类，请先查当前主图槽位和标签要求。”
- “这是本周活动价，把价格和活动条件直接生成在图里；以后变价时局部改字。”
- “我在豆包做详情页，标题、参数、FAQ、价格和法务都直接生成，不要无字底图。”
- “先给我整套详情页设计大纲，我确认后再一次写完每屏完整生图执行提示词，文字位置和字体都写清。”
- “我只给一张产品图，没有任何卖点资料。先整体调研，给我卖点信息大纲确认后再设计和生图。”
- “直接做整套，不用等我逐页确认，但不要编资料。”

## Troubleshooting

| 问题 | 处理 |
|---|---|
| 参考图很像，但产品变成竞品瓶型 | 确认用户产品图标为 P；构图/风格图只标 L/S；增加正侧背产品图并锁真实像素 |
| 整套像竞品长页或出现拼贴网格 | 把整条母本改为 SRC/ANALYSIS_ONLY；按屏提炼 L/T；未知权利第三方用文字规则或抽象线框 |
| 喜欢颜色但不喜欢参考版式 | 分开设置 styleWeight 与 layoutWeight，并分别点名 S 和 L 的允许/禁止维度 |
| Logo、二维码、证书被重画 | 标为 B/E + LOCKED_LAYER，确定性合成；二维码增加扫码、编号/OCR 校验 |
| 每一屏都像同一张产品居中图 | 回到模块和导演卡，改变景别、主体位置、信息密度或版式原型 |
| 中文、参数或表格错字/缺字 | 对照 VISIBLE_TEXT_BLOCK 做 OCR/目视逐字检查；用豆包局部改字只修错误区域，产品与构图不变；仍失败再重生该图 |
| 平台尺寸或槽位不确定 | 查询当前商家后台的“平台×类目×日期”规则；公开资料不足时标 PENDING |
| 没有每页资料 | 让 skill 检索并建立 F/K/Q/E/R/D/U 账本；不需要用户逐页填写 |
| 只有产品图，没有卖点资料 | 先收一份调研卖点信息大纲并逐项确认；确认前不让模型猜产品主张或进入生图 |
| 没有产品照片 | 可先完成研究、策略和提示词；成图只作为外观未锁定概念稿 |
