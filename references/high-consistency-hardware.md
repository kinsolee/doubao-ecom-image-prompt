# 高一致性：硬件 / 刚性装配产品（v3 增补）

本文件是 `production-pipeline.md` 与 `visual-reference-and-style-system.md` 的增补，
专门处理支架、转盘、折叠件、多关节 3C 等「多视角 + 刚性装配」产品。
当出现主体不一致、穿模、背景/中文污染、特写比例失真时，按本文件执行。

## 一、核心判断

扩散模型不理解刚性装配链，只按语义统计生成：锚图没有的视角靠脑补，
"可旋转 / 可调 / 360°"诱导它把活动部件画得到处都是（背面长连接头、托板分叉、竖杆悬浮）。

因此在 `P/B/E/L/T/S/C` 分工里：

- **P（产品）与 B/E（真实像素）是一致性的唯一来源**；style/layout 权重再高也不能替代；
- 凡真实参考能提供的像素，优先 B/E 锁定或合成，**不让模型凭语义重绘**；
- 只在 prompt 里写"保持一致"无效——必须给对应视角的真实像素。

**本方法论模型无关、不绑定 Doubao**：先产出模型无关规格（身份几何 / 材质 BRDF / 空间光影 / 光度镜头 / 文字 / 负向，整合全局 vector-feature-prompt-engineer 与 spatial-light-vector），再按目标生图后端编译（Doubao seedream 为当前默认；gpt-image 接入前先实测、不臆造参数）。规格与后端适配见 `doubao-product-content` 的 `references/model-agnostic-image-spec.md`、`references/image-backend-adapters.md`。

## 二、锚定图门（先于一切生成）

0. **货盘同款比对（先于分类，2026-09-27 负责人定案）**：采集链接常混入同链接下多个规格/家族（面板开孔图案不同、支撑结构不同、尺寸不同）。逐张先与**货盘 SKU 权威图**（`sku库存价格表.图片`，颜色+结构双重比对）对比：仅「面板形状/开孔图案/托钩/支撑结构/底座/比例」全部一致且颜色为本 SKU 颜色（或可作结构旁证的色变体）的图才可入参考池；异款（哪怕同链接同风格）一律排除，绝不进模型作主体参考。判定存疑（如仅背面、颜色不符）的不作身份锚。审计结论落参考池清单（图号+判定+依据），随执行包归档。
1. 全素材下载拼 contact sheet，按「视角 × 污染」分类；写结构事实卡（部件/数量/连接位置 +「没有」清单）。
2. 逐张判定是否「干净白底产品图」。**只有干净白底图能作 P 锚 / B-E 真实像素**：
   - 场景图、含独立标签/价格卡/手/手持设备的图，即使抠图也无法净化成白底产品图（分割会把手、设备、标签当前景保留，暖色背景只淡化）；
   - 这类图**不进模型作主体参考**，只可作 L/T（空间/版式）分析，且须隔离其中品牌与数据。
3. 合格锚图分割换纯白底、形态学清理；非本体标签/标题整段裁掉或采样背景覆盖，**本体真实印刷 logo 保留**。

## 三、多锚传输与视角约束

- 图生图/编辑**一次可传多张全角度参考（上限 6）**，不是只能挑 1 张；
- 每张成图传入**与该视角对应**的真实参考（画背面传背面图）+ 全局正面锚；脏锚图（中文/暖色）会污染结果，必须先净化；
- 没有真实支撑的视角不硬生成；表达旋转用**平面 2D 箭头 / 环形示意**，不叠多个旋转状态。

## 四、特写与尺寸：B/E 锁定，不重绘

- 转盘、关节、托钩、接口等特写，AI 重绘比例必然失真（高耸、过大）→ **从真实图裁剪 + 四边羽化合成**；
- 尺寸/参数图，AI 重着色会打乱数字 → **真实字体确定性绘制**（矢量部件 + 尺寸线 + 真实数字）；
- 裁剪 box 先网格 + 局部放大核定；反复重绘失败的画面一律回到真实裁剪，AI 不重绘本体。

## 五、Visual System：中性冷调

- 硬件套系统一**中性冷调**：白/浅灰台面、冷白光，**禁止木色、暖黄、香槟金**；同套颜色统一（银色款全银色）；
- 场景先生成冷调空镜，再合成真实产品；叠加顺序 **台面 → 台面层图形（旋转环等）→ 接触阴影 → 产品**，台面层先画才被底座正确遮挡，环心对准底座中心；
- 只能拿到暖调图时做色温冷化（只作用亮部，暗文字/黑转轴不动）。
- **物理比例硬约束（含道具场景）**：先建物理尺寸表（商品与每个道具真实 mm）；背景只生成空台面 + 虚化环境（不含同平面清晰道具），道具单体正放（长轴水平）抠图后按场景统一 mm→px 比例尺用 `physical_compose.py` 合成；AI 只定外观、尺寸由数学决定；物体收进台面不悬空 / 不探前缘，承托稳定，特写部件（转盘 / 接口 / 旋钮）按真实占比不放大增厚；过大物体（行李箱）前景部分出画体现大，不缩小失真。
- **真实感路线（原生同框，场景图首选，详见 `doubao-product-content/references/native-in-scene-rendering.md`）**：要真实照片感时，多角度净图作身份参考，用“身份保留 + 场景机位道具 + 真实感”三段式提示词，让模型把产品连同同一套光照、真实环境反射（金属反射真实窗 / 房间而非白棚光）、接触阴影 / AO、景深、颗粒原生画出；批量前先出 3–4 张探针、无字出图后叠文字。抠图合成仅在结构精确优先时用；真实抠图贴 AI 背景必有贴图感。
- **已验证坑**：兼容 / 示意线框 AI 必画成有厚度的实体设备或金属框 → 用 PIL 画纯空心单线；带平板 / 手机常被画成背面、遮挡托板 → 穿插正面黑屏图与无遮挡本体图。

## 六、文字与重音

- 图内文案随目标市场（巴西 pt-BR）；扩散模型常画错葡语重音（`ajustaveís`、`Compativél`）；
- 错字/重音用**整行重绘**：取标题上方干净背景逐列中位数填充，Arial Bold `anchor="ms"` 居中重写，不做单字修补。

## 七、与脚本的对应

上述确定性步骤的可运行脚本在 `doubao-product-content` skill 的 `scripts/`：
`clean_reference.py`（锚定图门/净化）、`real_detail_crop.py`（特写裁剪羽化）、
`deterministic_dimension.py`（尺寸图）、`cool_tone.py`（冷化）、`text_fix.py`（整行重绘）、`physical_compose.py`（统一 mm→px 比例尺物理合成 + 比例校验）。
本 skill 负责策划、参考角色分配与验收；确定性像素处理交给上述脚本。

## 八、验收增量

在三层验收基础上增加：缩略图并排时所有图为同一商品/同一颜色/同一冷调；
逐张对照事实卡数部件、数关节，无穿模悬浮；特写比例与真实图一致；尺寸数字逐字正确；**用像素比例尺核对同平面物体相对大小（像素比≈真实 mm 比，容差≤15%）与承托 / 接触关系，违背常识（电脑放不上支架、耳机与支架等大）即废稿；并过真实感关（同一套光、金属反射真实环境、接触阴影 / AO、景深颗粒自然，无白边、悬浮、抠图贴图感）**。

## 九、回写路径（URL 源 + material_syncer）

- 主图、详情图成品都先传图床得公开 URL，分别写「主图URL列表JSON」「详情图URL列表JSON」（两字段对称，schema 契约已含），经「同步任务」表触发或等 cron/event reconcile 到附件；多视角参考图走清空 + upload。
- **直接 upload 附件会被下一次 reconcile 用源 URL 覆盖**；同步组「源URL字段」名必须与表中真实字段完全一致，否则 Resolve 报 `source field not found`、整组"配置错误"不生效。写后读回核对数量与内容。

## 十、店铺商品图片套系生产清单（防复发，2026-09-27 J18 三轮返修沉淀）

下个商品的店铺商品图套系按本清单逐项过，缺一即返工：

1. **同款筛选**（第二节步骤 0）：采集链接全图与货盘 SKU 权威图逐张比对（颜色+结构），审计表落盘；异款（开孔图案/支撑结构/尺寸不符）与存疑图绝不进参考池。
2. **锚图净化**：锚图上的轮播 UI 残留（箭头/圆点/角标/文字标签）必须先修掉——模型会照抄垃圾；暖调实拍图先灰世界白平衡/冷化。
3. **真实像素优先**：背面、特写（钩/转盘/硅胶）、材质板一律真实裁剪合成，**不让 AI 重绘刚性结构**（AI 画背面开孔布局/比例必走样）；尺寸图=真实感产品照+确定性尺寸线标注，不画抽象示意方块。
4. **提纲差异化**：主图 9 槽（身份/旋转/调节/背面/尺寸/细节/便携/兼容/场景）与详情 8+ 屏（卖点清单/多视角真实宫格/材质/机理/功能/多场景/参数总表/兼容+实收）资产类型、视角、文字密度必须拉开；详情屏文字量显著多于主图（参数行/说明段），连续屏禁止同角度同构图重复。
5. **文字**：场景图无字出图→确定性叠字（pt-BR 重音 100%）；尺寸/参数数字只走确定性绘制；无证据的清单项（如赠品/证书）与效果承诺（如"防刮花"）不入图。
6. **探针先行**：批量前出 3 张探针（正面 hero / 结构最高风险位 / 竖版首屏），过身份+真实感双闸再批量；构图类 brief 必须写明「产品完整可见+边缘留白」，否则主体会被裁出画框。
7. **模型路由（2026-09-27 负责人定案）**：豆包工作台环境**优先 seedream 旗舰**生图；本机 GPT（opencodex 池）通道保留接入作**切换备选**——该通道不回显实际模型、model 字段疑似被忽略，质感不达标时直接切换模型（执行包=提示词+纯净锚图随包迁移），不在单一通道反复重抽。
8. **回写**：OSS 上传→主图/详情图 URL 源字段→附件直传（与 URL 同字节）→图片套ID 版本递增→逐字段读回；部分替换时未变槽位保留既有 URL/附件，不整组重传。
9. **SKU 侧核对**：写入/回填 店铺SKU 后核对 商家SKU/变体图 非空（2026-09-21 前旧批次存在缺 商家SKU 遗留），缺则按关联 ERP SKU 补齐并读回。
