# 参考图迁移提示词与迭代模板

主要服务模式一。主图套系读取 [main-image-set.md](main-image-set.md)，复杂单图和详情页逐屏读取 [detail-page-prompt-spec.md](detail-page-prompt-spec.md)，参考权利、长页分屏和 Visual System 读取 [visual-reference-and-style-system.md](visual-reference-and-style-system.md)，多图编译读取 [project-packet-and-prompt-compiler.md](project-packet-and-prompt-compiler.md)。目标是把参考图的**构图、光影、色彩关系、镜头与信息层级**迁移到用户产品，不复制第三方产品、品牌、文字、数据和专属创意资产。

## 一、交付顺序

1. 参考图拆解与可迁移/不可照搬清单；
2. 用户产品事实、已确认卖点信息大纲（如触发）与视觉资产；
3. “画面 / 图内文案 / 设计指引”迁移策略卡；详情页先有整套设计大纲，再展开全部逐屏执行稿；
4. P/B/E/L/T/S/C 语义角色、授权、传输方式、style/layout weight 与冲突维度；
5. Visual System 与五层源卡，编译为一条完整自足中文提示词；
6. 反推任务未指定数量时给 4 个方向：忠实迁移基准、构图升级、场景叙事、信息设计；用户明确只要一张或构图已锁死时可缩减；
7. 选中方向的高质量提示词/完整图文成片、VISIBLE_TEXT_BLOCK、局部改字和验收标准。

多图套系不为每屏机械出 3 个版本；只对首图、首屏或高风险锚点探索。

## 二、迁移映射表

```text
| 参考图机制 | 为什么有效 | 保留到用户图的抽象规则 | 必须替换 | 用户事实/证据 |
| 产品偏右、左上留字 | 形成 Z 型或对角动线 | 产品位于右下视觉重心，左上保留标题安全区 | 参考产品/包装/标题 | P01/F01 |
| 冷暖双光 | 强化材质层次 | 暖主光 + 冷轮廓光，控制高光 | 第三方品牌色 | S01 |
```

必须把“看起来像”翻译成可执行关系；不能只写“参考原图风格”。第三方专属瓶型、吉祥物、字体商标、代言人、logo、文案和数据列为不可照搬。

## 三、参考角色说明

- 图 1 `P`：用户产品身份锚，作为外形、比例、包装、标签、颜色和数量的最高优先参考；仅上传参考图不等于像素锁；
- `B`：logo、字标、二维码、授权图形和监管标识，默认锁定像素合成，不让模型重画；
- `E`：用户真实证据，原样放置或只分析，不由 AI 重画/补编号；
- `L`：只控制标题带、区块比例、主体位置、安全区和留白；
- `T`：只控制字级、对齐、卡片/表格骨架和信息密度，不复制文字；
- `S`：只控制色彩关系、光、材质气质和后期；
- `C`：已通过成图，锁本族光色、材质、母题与边缘连续性，不复制整页构图。

整条第三方详情页、模板拼贴和情绪板母本只作 `SRC + ANALYSIS_ONLY`；不得直接传模型。自有/授权完整单屏裁片才可按 L/T 使用，未知权利第三方只转文字规则或去内容抽象骨架。

按维度解决冲突：产品听 P，品牌听 B，证据听 E，主张/限制听已准入 SP/claim/F/R，空间听主图策略或详情页大纲 + 当前执行稿 + L/T，风格听 Visual System + S/C。styleWeight 与 layoutWeight 独立，所有维度都不得覆盖 P/B/E/F/R。模型只支持一张参考时按 fidelity route 优先 P；P 已像素锁时可选择 C/L/S。多参考图由 provider 重新连续编号并逐张点名，不能写“综合参考”。

## 四、单图完整提示词模板

任务元数据先锁定：主图填 `countMode / templateId / imageSlot / defaultRole / resolvedRole / adaptationReason`；详情页填 `moduleId / moduleInstanceId / Dxx`。这些都嵌入“设计指引”，不新增用户可见的第四个一级项。

```text
为〔目标平台/图位〕制作一张〔品类〕电商图，画幅按〔Rxx/用户尺寸〕。本图任务是回答“〔购买疑问〕”，第一落点是〔产品/核心信息〕，第二落点是〔短标题/证据或场景〕。

本提示词由〔GLOBAL_CONSTANTS 版本〕+〔FAMILY_ANCHOR 版本〕+ 本图 IMAGE_DELTA + VISIBLE_TEXT + ACCEPTANCE 编译；最终文本自足，不依赖“同上”。

资产协议：〔P/B/E/L/T/S/C assetId、authorization、transferMode、允许/禁止维度〕；产品保真路线为〔PIXEL_LOCK_COMPOSITE / RELATIONAL_GENERATIVE_EDIT / CONCEPT_ONLY〕；styleWeight=〔值〕，layoutWeight=〔值〕。B/E 使用锁定真实像素或仅分析；整条长参考页和 analysis-only 第三方原图不进入模型。实际模型参考共〔N〕张并逐张点名：参考图1〔assetId/角色/只控制什么/禁止什么〕；参考图2〔……〕。产品听 P、品牌听 B、证据听 E、主张听 F/R、空间听策略卡+L/T、风格听 Visual System+S/C。

画布采用〔构图/网格〕，四周安全区〔比例〕。产品位于〔位置〕，占画面〔比例〕，朝向〔角度〕；标题安全区在〔位置/比例〕。视觉动线从〔第一落点〕到〔第二落点〕再到〔收尾〕，背景细节保持次级。

产品为〔完整的用户产品描述〕，共〔数量〕件，必须保留〔身份特征清单〕。只有 PIXEL_LOCK_COMPOSITE 路线可要求真实包装像素不变；RELATIONAL_GENERATIVE_EDIT 只能以高保真为目标，并在生成后恢复/重贴不准确标签。前景〔对象、遮挡与焦度〕，中景〔产品与动作〕，后景〔环境、深度与留白〕。道具只有〔清单〕，分别表达〔真实含义〕；与产品的接触、尺度和光向可信。

摄影机位〔高度/俯仰〕，等效〔焦段〕，〔景别〕，焦点在〔细节〕，景深〔范围〕，不使用夸张广角。主光从〔方向〕以〔软硬/色温〕照射，补光在〔方向〕，轮廓光勾勒〔边缘〕；阴影向〔方向〕延伸〔长度〕，接触处最实，标签不过曝。

主色〔Hex/占比〕，辅色〔Hex/占比〕，点缀色〔Hex/唯一用途〕；产品与背景通过〔明度/冷暖/色相〕对比。表现〔产品材质〕的〔反射/折射/纹理〕、〔环境材质〕的〔纹理〕和〔液体/食物/织物〕的〔具体物理状态〕，避免塑料蜡感。

文字按 `textId/semanticType/claimId/SP-ID/F-E-K-D-R/qualifierTextIds/exactString/renderedLines/region/box/maxLines/完整 typography/relationToProduct/validation` 隔离，并按 semanticType 强制来源。把已确认文案交给豆包直接渲染；每个 textId 完整写精确原文、强制分行、框位、行数、字体类别/气质、字重、字号、HEX、对齐、行距、字距、底色对比及产品关系。标题、副标题、卖点、标签、参数、表格、FAQ、价格和法务逐块展开，不写“同上”。所有文字实际入图；布局指令不属于可见字符串，白名单外不新增文字、数字、logo、水印或徽章。

输出真实精致的商业成片：产品身份准确、版式克制、材质可信、光影物理一致、缩小后层级仍清楚。禁止〔本图最可能的产品错误〕、〔事实错误〕、〔物理错误〕、〔文字错误〕。验收：〔产品保真〕、〔第一落点〕、〔OCR〕、〔平台规则〕均通过。
```

提示词必须单独成立。不得只写“和参考图一样”；不得用“高端、8K、电影感”替代布局、镜头、光与材质。

## 五、信息图和机制图

只有事实账本确认某成分/结构/工艺确实属于本品，且画面不会夸大结果时才做机制可视化。

```text
背景/空间层：底色、材质、留白与网格；
产品/事实层：用户产品 + 真实原料/真实结构/真实流程节点；
关系层：用统一细线、箭头、编号说明真实关系；
文字层：标题、参数、解释、编号和限定条件全部由豆包在成图中直接渲染；
证据层：真实 E 资产原样放置。
```

禁止默认添加“发光活性粒子、分子线、DNA、人体器官、实验器皿、英文小字”制造专业感。抽象几何、粒子或光带只作为风格元素，不得暗示未证机制；证书、检测、专利、专家与数字不由 AI 生成。

## 六、豆包文字直出

所有图内文字每条使用 canonical schema 与完整排版 tuple；文字组数由内容和可读性决定，不设 0–2 组上限。标题、副标题、卖点、标签、参数、营养/配料、尺码、FAQ、比较表、价格/优惠、法务与来源全部写入 prompt 并实际出现。可见白名单与布局说明分离，生成后按强制分行做 OCR，并目视核对字体、框位和产品避让。

## 七、受控变体

先记录参考图的 `referenceQualityFloor`：主体尺度/落点、版式与留白、光影层次、材质细节、色彩关系、文字融合中最关键的 3–5 项。每个变体保留这些承重机制，只改 1–2 个主变量；四个方向不能只是换颜色、背景或道具：

| 变量 | 例子 |
|---|---|
| 产品位置 | 右侧 55% → 左侧 55%，标题区相应对调 |
| 镜头 | 平视 70mm → 轻俯拍 50mm |
| 背景空间 | 无缝棚拍 → 真实早餐桌，产品尺度不变 |
| 光 | 大面积柔光 → 硬窗光长影，色盘不变 |
| 版式 | 编辑式主视觉 → 1+2 场景矩阵 |

生成后把每张与品质基线对照。主体层级、光影、材质、版式或文字融合有两项明显退化时，先修提示词、参考角色或锚点，不把更弱的结果当作“创意变体”。

若跨平台适配，先查当前 `Rxx`，重新排版并检查安全区；不是把同一图机械裁成 1:1、3:4、9:16。

## 八、品牌/套系 Visual System

```text
Visual System 版本、来源模式与授权：
品牌气质与反面边界：
主/辅/点缀/文字色、比例、来源与 exact/guide：
网格、安全区、标题基线：
字体类别/气质、各层级字重、字高占画布比例、HEX、对齐、行距、字距：
圆角、描边、图标和分隔线：
摄影、镜头范围、主光与阴影：
产品尺度与标签方向：
背景/台面材质、构图族、融合方式、密度节奏与场景族：
styleWeight / layoutWeight：
P/B/E/L/T/S/C 资产与 transferMode：
渠道适配与上下衔接：
固定禁止项：
```

Visual System 锁系统，不锁死每张构图。相邻图通常在景别、产品位置/尺度、信息密度、信息拓扑、背景类型中至少变化两项；连续对照序列可例外。参考图肉眼估色只能标近似引导，正式品牌色才是确定性值。

## 九、生成与局部修订

1. 关键锚点只有存在真实待决变量时才做 1–4 张低/中成本草案；构图已严格指定时一张即可；
2. 选定后固定 P、构图、相机、色盘和主要道具，再高质量生成；模型支持 seed 时才锁定 seed，否则用选中成图、P/B/E 真实参考与场景族锚维持连续性；
3. 每轮编辑都重述必须保留的产品、构图、光和文字区；
4. 任何文字错字、漏字或多字都先用豆包局部改字，只修对应文字区，之后重新检查产品差异与全图 OCR；
5. 使用稳定 job ID、Visual System/锚点版本、输入 hash 和 QA 状态；D 变化优先用豆包局部改字或只重生该图，单张 L/构图变化只重生该图，场景族锚变化只级联该族；
6. 产品身份或整体空间错误才整图重做；恢复任务只续跑缺失/失效 job，不覆盖已通过成片。

### 差距诊断

| 现象 | 上游原因 | 修改 |
|---|---|---|
| 产品不像/包装漂移 | P 不清或被 S/L 覆盖 | 增加正侧背 P、列身份特征、提升输入保真、锁真实像素 |
| 精致但不卖货 | 唯一任务/第一落点缺失 | 回到导演卡，删装饰，重排层级 |
| 画面平/假 | 光源与材质不具体 | 写主补轮廓、阴影、粗糙度、反射/折射和接触关系 |
| 过度模板化 | 连续使用同一原型 | 改景别、位置、信息密度或生活动作 |
| 中文错/乱 | 文字块指令、行断或位置不清 | 逐块重述精确字符串，用豆包局部改字并重做 OCR |
| 图有伪科学感 | 用通用粒子/分子替代证据 | 删除，换真实材料、结构、标签或中性信息设计 |
| 平台不通过 | 规格/叠字/槽位过时 | 回到 R 规则预检并重新排版 |

## 十、生成后检查

产品归属与保真、SKU 数量、文字 OCR、平台规格、事实/证据、动态字段、物理接触、缩略图/移动端层级、第三方 IP、AI 声明全部通过才交付。详细三层验收见 [production-pipeline.md](production-pipeline.md)。
