# 详情页整页设计（模式二）

详情页不是把产品换十次背景，也不是固定九屏模板，而是一条连续的购买决策路径。先解决“这是什么、是否适合、依据是什么、怎么选、有哪些限制”，再用统一视觉系统把每个答案做成独立屏。生产时一屏一图，在豆包中直接生成完整画面与文字，校对后再拼接。

- 共用流程、确认门、参考角色、完整可见文字和验收：[production-pipeline.md](production-pipeline.md)
- 资料不足时的检索与文案：[product-research-and-copy.md](product-research-and-copy.md)
- 逐屏源卡与提示词：[detail-page-prompt-spec.md](detail-page-prompt-spec.md)
- 视觉基因、参考资产、长页分屏锚与 Visual System：[visual-reference-and-style-system.md](visual-reference-and-style-system.md)

## 一、详情页状态机

```text
渠道/SKU/节奏定义 → 输入/资产/OCR观察与身份审计
→〔必要时：Stage 0 同 SKU/规则/买家调研 → 调研卖点信息大纲 → Research Gate 用户确认〕
→ 确认事实范围 + 视觉基因/灵感 → 模块候选
→ Stage A：整套详情页设计大纲 → Gate 1 大纲确认
→ Visual System Contract → Stage B：全部逐屏详细设计执行稿 → Gate 2 执行稿确认
→ 首屏/必要场景族锚检查 → manifest + 五层逐屏生产包
→ 豆包逐屏生成完整图文 → 局部改字/拼接与三层验收
```

用户只是没有提供“每页写什么”、但已有完整合格卖点集时，不把逐页填表任务退回用户，直接代拟设计大纲。若只有产品图/零散身份规格且无完整合格卖点集，必须先完成 Stage 0 并确认卖点大纲；“主动补齐”不等于替用户决定或证明卖点。

## 二、Stage 0：调研卖点信息大纲（条件触发）

触发条件：`详情页任务 + 只给产品图或只有身份/零散规格 + 不存在完整、已批准、证据合格的本 SKU 卖点集`。单一净含量/尺寸不自动豁免。先做包装/OCR 观察与 SKU/版次识别；身份不清时只问一个避免搜错商品的最小问题。然后按 [product-research-and-copy.md](product-research-and-copy.md) 调研同 SKU 官方事实、权威类目知识、买家疑问、真实证据入口和当前平台规则。

本阶段只交付独立的`调研卖点信息大纲 vX`：产品身份/置信度、来源与日期、已核事实、买家问题、SP 候选池、每项 evidenceStatus（可直接用/需核实/仅类目教育/禁用）、selectionStatus（待选/采用/修改/拒绝）、Top 1–3、冲突和确认清单。不要提前写视觉设计大纲或逐屏提示词。

### Research Gate

- 必须取得用户对 SKU、候选卖点采用/修改/不采用、事实范围和待补证据的明确回复，才能进入 Stage A；
- 用户点头只批准信息选择，不会把 `K/Q/U`、竞品观察或搜索摘要变成 `F`，高风险主张仍需真实 `E`；
- `FAST` 也不能内部代批；`PROMPT_ONLY` 默认停在本门，因为产品主张型 prompt 同样依赖确认；
- 联网不可用时交付证据受限版大纲并说明缺口，不伪造来源。除非用户明确把范围缩成无卖点的身份概念图，否则不继续生图。

Research Gate 通过后，把确认版本记为 `selling-point-outline@vX`。后续视觉研究、设计大纲和逐屏执行只能引用其中准入的 `SP/F/E/R/D`；设计修改不能反向抬高证据等级。

## 三、决策叙事：先信息，后情绪

默认优先级不是固定 AIDA，而是根据商品和渠道排列下列问题：

1. **商品身份**：品名、SKU、售卖单位、包装/形态到底是什么；
2. **核心选择理由**：最值得继续看的 1–3 个本品事实；
3. **依据与机制**：原料/材质/结构/工艺/数据怎样支持理由；
4. **适合与限制**：人群、场景、尺寸、兼容、储运、使用前提；
5. **选择与履约**：规格、组合、实收内容、价格条件、物流和售后；
6. **信任与行动**：真实证据、品牌信息、FAQ 与购买收口。

不同商品重排：

- 低决策成本商品：身份 → 核心理由 → 场景/规格 → 实收/履约，短而完整；
- 高客单或复杂 3C：身份 → 参数/兼容 → 结构证据 → 使用 → 服务；
- 服饰：身份/版型 → 材质 → 尺码与上身 → 细节 → 洗护/售后；
- 食品：身份/售卖单位 → 配料/风味/标签 → 食用场景 → 储运/规格；普通食品不以症状痛点或功效开场；
- 易误购品类：关键限制、购买须知和适配条件前移，不先讲空泛品牌故事。

## 四、M1–M8 详情页模块库

`M1–M8` 是唯一对外模块协议，但**不是固定八屏**。每个模块标 `INCLUDE / MERGE / TEXT_ONLY / OMIT / PENDING`；一个模块可实例化成多屏（如 `M2-01/M2-02`），多个模块也可合并为一屏。具体图片仍用 `D01/D02…` 作屏号，避免把模块数误当屏数。

| 模块 | 目的与默认内容 | 启用/替代规则 |
|---|---|---|
| M1 首屏痛点共鸣 | 3 秒内建立“说的就是我”的相关性，同时让产品身份清楚；从购买困惑、使用不便、期望场景或安全痛点切入 | 普通食品、受监管品类或无功效证据时，改成需求/疑问/使用时刻共鸣，不用症状、恐吓、人体器官或前后效果 |
| M2 核心优势铺开 | 把 Top 2–3 卖点逐项展开；每个实例采用“问题/需求 → 产品方案 → 事实佐证” | 只用 `ELIGIBLE + ADOPTED` SP；一屏一个核心理由，可拆 2–3 屏，不把多个卖点塞成口号墙 |
| M3 配方/工艺纵深 | 配料/材质可视化、工艺/结构流程、营养/参数数据；按产品实际拆分 | 仅使用已核本 SKU F 与真实 E；类目 K 保持类目主语，示意图标“示意”，不虚构内部结构、分子、实验室或工艺 |
| M4 使用场景 | 默认 2–3 个典型场景带入，可用三格、连帧或多屏；呈现动作、尺度和使用价值 | 场景必须真实且回答购买问题；只有一个高价值场景时可做沉浸单场景并说明，不为三格凑人物/道具 |
| M5 品牌/资质背书（可选） | 品牌简介、真实专利/证书/许可证、产地/工厂/报告或服务事实 | 品牌文字绑定 F；证书、专利、报告、工厂等必须有真实授权 B/E，缺失则 `OMIT/PENDING`，模型不得重画 |
| M6 规格参数 + 竞品对照 | 参数表、尺寸/规格/SKU/实收内容；有资格时加入同条件差异表 | 参数绑定精确 F；竞品/数据比较另过对象、条件、单位、来源、范围和有效期门。证据不足时改为本品参数 + 适合/不适合或同品牌 SKU 选择表 |
| M7 FAQ | 从卖点与研究反推约 6 个真实未决疑虑，默认 5–7 题；最后一题固定为“产品属性/适用边界 + 必要声明” | 模块按需启用但启用后不得用填充题凑数；末题绑定已确认身份和 R/F，免责声明不能挽救前文无证或误导主张 |
| M8 购买引导 + 法务声明（可选） | 产品全家福、购买理由回顾、CTA、价格/赠品/物流/服务，以及适用的完整版声明 | `R` 允许且 `D` 的 SKU/地区/期限/条件齐全才写动态信息；CTA 不伪装系统按钮，法务只写适用内容，缺失时用规格/实收/储运收口 |

模块准入：高优先级买家问题 + 有证据/安全场景 + 渠道允许 + 不重复 + 适合视觉表达。屏数是设计结果；不得把 M1–M8 全部强制启用，或机械推导成八屏。

无论 Stage A 大纲还是 Stage B 执行，每个入选模块/屏对用户只输出三个一级项：**画面 / 图内文案 / 设计指引**。事实、SP、证据、版本、状态、拆/并屏理由和验收都内嵌在“设计指引”，不另加第四项。

### FAQ 与法务的处理

- M7 启用时以约 6 个真实问题为默认结构，正文已回答的问题不重复；研究后仍不足时允许少于 6，但必须说明，不制造填充问题。
- M7 最后一题必须承担产品属性/适用边界和必要声明；无免责要求时写客观边界，不强塞空泛法务话术。
- M8 完整声明按需启用；限定条件仍须在对应主张附近出现，末屏只能汇总，不能用小字挽救前屏误导。

### 视觉方向与参考准入

- 用户没有风格参考时，从商品身份、购买任务、货架差异、品牌正/反面气质、材料、场景、渠道和风险提取视觉基因，研究 2–4 个可生产方向；不直接询问用户“每页想要什么风格”；
- 视觉候选必须说明它适合哪些屏型、产品几何和移动端层级，不能只给一组情绪形容词；
- 事实来源与视觉来源分账。竞品详情页不证明本品事实；其中产品、品牌、文案、数据、证据与专属元素不得迁移；
- 整条长参考页登记为 `SRC + ANALYSIS_ONLY`，先建立 screen map；自有/授权裁片可按 L/T 使用，第三方未知权利原图只转成文字规则或抽象线框；
- styleWeight 与 layoutWeight 分开，且永远不能覆盖 P/B/E/F/R。

## 五、Stage A：详情页设计大纲

进入设计前应至少知道：产品身份与售卖单位、一个可核验购买理由（或用户明确批准无主张身份概念范围）、影响选择的规格/限制；目标平台当前关键规则应已核验，或明确记为 `R=PENDING / 未联网`，按保守通用画幅做 provisional 设计且不承诺合规，上架前再复核。产品视觉外观应已知，或明确记录为 `U/PENDING` 并采用“外观未锁定概念模式”。缺逐屏内容时按 [product-research-and-copy.md](product-research-and-copy.md) 形成情报包；若曾触发 Stage 0，还必须引用用户确认的 `selling-point-outline@vX`，不能用未确认候选补屏。视觉方向至少有品牌正/反面词和一个可执行的摄影/版式假设。只有上架级定稿前，用户产品图 `P` 才是硬门。

先交付一份能独立评审的整套大纲。它锁定“为什么这样讲、每屏讲什么、整套如何统一又不重复”，此时不提前用长提示词填满页面。推荐结构：

```text
# 详情页设计大纲 vX

项目定义：平台/站点/类目/端、SKU、售卖单位、目标人群、购买任务、交付范围、画幅依据。
上游卖点大纲：未触发 / selling-point-outline@vX（用户确认时间、采用 SP-ID、仍禁用项）。
事实与风险边界：可用 F/K/E/R/D、不得入图 U、比较/功效/动态字段边界、P/B/E 资产状态。
核心设计命题：一句总策略；本套最重要的视觉记忆；明确“不做成什么”。
Visual System 预设：品牌正/反面气质、主辅/点缀/文字色及 HEX、字体层级、网格/安全区、摄影/光/材质、图形语言、移动端原则。
购买决策叙事：开场 → 理由 → 依据 → 场景/选择 → 信任/收口；说明为何这样排序。
模块取舍：M1–M8 的 INCLUDE/MERGE/TEXT_ONLY/OMIT/PENDING、moduleInstanceId、预计屏数及理由；模块数量不等于屏数。

按入选模块顺序逐个输出三项式大纲卡：

M#｜模块名｜状态｜moduleInstanceId / 对应 D 屏号
画面：本模块的视觉概念、主要产品状态、信息载体、构图/场景族、可能的拆屏或合屏方式。
图内文案：准确标题、副标题、数据、规格、FAQ/CTA/法务素材与必要限定；此处锁文案素材，不写完整长 prompt。
设计指引：模块目的、买家问题、唯一信息、SP(evidence+selection)/claim/Q/F/K/E/R/D、取舍与拆并理由、信息密度、L/S/T/C、上下承接、风险与待确认项。

场景族与锚定规划：按环境、光型、镜头、材质分族；指出首屏和必要锚屏，不机械每族都做锚。
完整文案素材：按屏列出不可丢失的标题、数据、规格、来源和限定条件；未知项明确 PENDING。
节奏与连续性校验：疏密、产品位置/尺度、构图多样性、上下边缘、首尾回扣。
待确认项：只列会改变产品身份、事实边界、屏序或视觉方向的项目。
```

大纲要求：

- 一屏一个主问题；如果标题需要“以及、同时、还有”才能成立，优先拆分或重写；
- 每个模块大纲卡只使用画面/图内文案/设计指引三个一级项；模块状态、证据与内部绑定放入设计指引，不另开第四项；
- 连续两屏不得同时“产品居中 + 顶部大标题”；相邻屏通常至少在产品位置、尺度、镜头、密度、信息拓扑中变化两项，连续规格/步骤序列可说明理由后例外；
- 大视觉、微距、信息板、场景和参数屏形成疏密节奏；
- 画面道具必须能一一解释其语义，无关装饰删除；
- 所有文案素材中的主张绑定事实或证据 ID，动态商业信息绑定 `D`；
- Visual System 预设必须足以判断整套气质和排版方向，但不替代后续逐屏执行；
- 大纲只确定页面级意图和准确文案素材，不把“高级感、苹果、产品居中”之类泛化短句冒充设计方案。

## 六、Gate 1：只确认设计大纲

`STANDARD` 在这里停一次，让用户确认：屏数/模块、决策顺序、每屏唯一信息、逐字文案素材、Visual System 方向和待确认项。此门确认视觉设计大纲，不重复或替代 Research Gate，也不改变事实等级。此时不同时交付全部长提示词；如果用户修改屏序或主张，先更新大纲版本，再进入 Stage B。

- `FAST`：内部形成大纲、完成事实/参考权利/构图重复/风险自审并锁版本，不在对话中暂停；
- `PROMPT_ONLY`：先清晰输出大纲，再输出 Stage B 全部逐屏执行稿；不为不存在的实际生图制造确认门；
- 用户明确只要“大纲”时，到 Gate 1 即可，不擅自展开逐屏长 prompt。

## 七、Visual System Contract 与长页版式锚

Gate 1 后把视觉方向锁成可版本化 Visual System，而不是一段“高级、清新、电影感”的描述：

1. 品牌气质：3 个有边界的正向词，并写 3 个反面气质；
2. 核心视觉母题：一个能贯穿而不喧宾夺主、且不暗示虚假事实的概念；
3. 色盘：主/辅/点缀/正文/状态色、角色、比例与来源；官方色标 exact，参考图视觉估色标 design-inference；
4. 网格：目标画布、列数、左右安全区、标题基线、卡片间距和上下过渡带；
5. 字体系统：眉线/标题/副标题/正文/数字分别定义字体类别/气质、字重、字高占画布比例、HEX、行距、字距和对齐；逐屏 prompt 仍写本屏实际值，不只引用母版；
6. 形状系统：圆角、描边、图标线宽、分隔线、数据组件和禁止的卡片堆叠；
7. 摄影：棚拍/生活/3D/混合、镜头范围、景深、锐度和产品修饰边界；
8. 布光：主光方向、软硬、色温、补光、轮廓、阴影与高光控制；
9. 材质：产品与环境表面的可见物理特征；
10. 构图与融合：composition families、integration methods、layoutFingerprint 和允许例外的 anti-repeat 规则；
11. 节奏与场景族：按环境、光型、镜头和材质关系设置，可为 1 个或多个；记录产品尺度范围和疏/密屏交替；
12. 参考系统：P/B/E/L/T/S/C 的 assetId、授权、transferMode、允许/禁止维度；styleWeight 与 layoutWeight 分开；
13. 渠道、过渡与禁用：listing/detail/ad 适配、上下边缘色、连续元素和固定禁止项。

如果输入是整条长详情页：母本登记为 `SRC + ANALYSIS_ONLY`；建立 `y 边界 → 屏功能 → 版式 → 文字密度 → 上下过渡` 的 screen map；按语义屏裁完整屏，不切标题、产品、卡片或阴影，不上采样；每个目标屏通常只分配一个主 L。自有或授权裁片才可 `MODEL_REFERENCE`；第三方未知权利原图只转 `PROMPT_SPEC` 或无内容抽象线框。整条母本永不进入 modelReferences。

字体字号与画布只给相对规则；最终像素依据 `Rxx` 和真实上架后台，不把 750/790/990 写成永久平台通则。完整 schema 和参考权利规则见 [visual-reference-and-style-system.md](visual-reference-and-style-system.md)。

## 八、Stage B：全部逐屏详细设计执行稿

Gate 1 通过后，依据已确认大纲一次完成全部屏，按屏号顺序写入同一执行包；不得写一屏就询问一次。每屏只有三个一级项，便于用户审阅，但第三项内的豆包提示词必须完整自足：

```text
屏 Dxx｜名称｜moduleId=M# / moduleInstanceId=M#-##｜对应大纲版本/购买疑问

1. 画面
```

### Gate 2：统一确认执行包

`STANDARD` 在全部屏执行稿完成后只停一次，确认文字、排版、产品状态、视觉系统、场景族和参考分工。若某屏改动影响屏序/事实/全局风格，先升级大纲或 Visual System 版本并级联受影响屏；局部构图或字排只改该屏。`FAST` 内部通过相同检查后继续；`PROMPT_ONLY` 交付到这里即完成，不声称已生成图片。

## 九、锚定图与逐屏生产包

Gate 2 通过且任务要求实际生图时：

1. 只有存在真实待决变量时，先做 1–4 个低/中成本首屏草案，每张只改变 1 个主变量；构图已严格指定时一张即可；
2. STANDARD 展示首屏/必要场景族锚并检查产品保真、B/E 完整性、第一落点、色盘、光型、排版骨架与真实文字；锚点未通过就修锚点或 Visual System，不带病批量；
3. 简单套系可以只有 1 个场景族；只为与首屏差异最大的族增加锚点，不机械每族多次出图；
4. 每张后续屏都能访问 `P` 或锁定 P 层，并按需使用本族 `C`，不能只在总说明中写一次；
5. provider adapter 重新编号实际参考，prompt 逐张点名 assetId、角色、允许/禁止维度，条数 1:1；B/E 默认真实像素约束，不让模型补造；
6. FAST 内部通过同一锚点检查后自动续跑；PROMPT_ONLY 只标计划锚点，不伪造已生成锚图。

每屏先填 [detail-page-prompt-spec.md](detail-page-prompt-spec.md) 的生产源卡，再编译模型提示词。交付：

1. 经 Gate 1 确认的设计大纲版本和 Gate 2 确认的本屏执行稿；
2. Visual System 版本与本屏 family/composition/integration/layout fingerprint；
3. P/B/E/L/T/S/C 资产角色、授权、transferMode、权重与冲突维度；
4. 稳定 job ID、依赖、F/E/R/D、输入/输出版本和 QA 状态组成的逻辑 manifest；
5. 画幅、网格、安全区、产品/文字/信息/过渡带比例；
6. `GLOBAL + FAMILY + DELTA + VISIBLE_TEXT + ACCEPTANCE` 五层源卡和编译后的完整自足中文提示词；
7. 豆包完整图文成片、VISIBLE_TEXT_BLOCK、OCR/目视校对与局部改字规格；
8. 针对性禁止项与验收标准。

硬规则：

- 一屏一提示词、一屏一张独立高分辨率图，不一次生成整条长页；
- 每屏重申产品数量、外形、包装、标签方向、颜色、状态和不可变元素；
- 整条参考长页不进入任何屏的 modelReferences；L/S/T/C 逐张点名，未授权第三方只作分析或文字规格；
- 只编译适用字段，优先写清产品、关系、镜头、光、材质与版式，不为 500–1000 字凑词；
- 可见文字逐块使用 compiler canonical schema 隔离：`semanticType/claimId/sellingPointId/F-E-K-D-R/qualifierTextIds/exactString/renderedLines/region/box/maxLines/完整 typography/validation`；标题、副标题、卖点、参数、FAQ、价格和法务逐字直出并校对；
- 证书、报告、真实工厂/产地/实验室和资质只使用 `E` 资产，不由模型生成；
- 相邻屏通常在景别、产品位置/尺度、信息密度、信息拓扑、背景类型中至少改变两项；连续规格/步骤序列例外需说明。

## 十、上下衔接与拼接

- 预先记录每屏顶部色与底部色；需要无缝拼接时在上下留干净过渡区，不放主体、文字、卡片或被切阴影；
- 外边距、标题基线、卡片圆角、图标线宽统一；产品位置可左右交替；
- C 只锁本族光色、材质、母题和边缘衔接；不沿用锚图的产品姿态或整页构图。每屏 layoutFingerprint 用于检查“统一而不重复”；
- 跨屏光带/丝带只在模型和后期能准确对齐时使用；否则用色彩、台面或留白完成节奏；
- 先检查单屏，再按顺序拼接预览；返修只处理问题屏/问题层。

## 十一、详情页验收

| 层 | 合格标准 |
|---|---|
| 规则 | 画布、文件、必备信息与 AI 声明符合当前 `R` |
| 事实 | 所有产品主张绑定 `F/E`，类目知识未偷换成本品效果 |
| 产品 | 包装、标签、颜色、数量、比例和 SKU 跨屏一致 |
| 决策 | 身份、理由、选择、限制、实收/履约等高优先问题已覆盖 |
| 文案 | 所有已确认文字实际出现在成图中；OCR/目视逐字通过；限制邻接 |
| 视觉 | Visual System 版本统一；style/layout 权重未串线；相邻版式指纹有节奏；手机端层级清楚 |
| 参考 | 长页母本未直传；模型参考逐张点名 1:1；L/S/T/C 无竞品产品、文案、数据、logo、配色或占位图泄漏 |
| 物理 | 材质、光向、阴影、液体、遮挡、人物接触关系可信 |
| 证据 | B/E 原样、二维码可扫、编号/OCR 一致；无假工厂、实验室、专家、证书、专利、报告、评价、销量 |
| 拼接 | 过渡自然，无文字、阴影、产品或卡片被切断 |
| 商业 | 标题、SKU、主图、详情和投放/直播口径一致，动态字段有效 |

不合格时先判断问题属于事实、母版、产品、背景、可见文字区还是单个局部；文字错漏优先豆包局部改字。事实、产品身份或母版问题才回滚所有受影响屏。
