# 主图与商品图库系统

本文件用于首图、副图、商品图库和用户指定的“五张主图”。核心原则：**用户明确要 5 张且未另定顺序时，默认执行 `FIVE_CONVERSION_ARC_V1`；未指定张数时，才按平台×类目规则与购买决策自适应。** 五图是用户固定数量下的默认槽位语义，不冒充平台永久通则。若组合任务只有产品图/零散身份规格且无完整、已批准、证据合格卖点集，先通过 [product-research-and-copy.md](product-research-and-copy.md) 的 Research Gate；主图也不得抢先用未确认卖点。视觉参考与 Visual System 读取 [visual-reference-and-style-system.md](visual-reference-and-style-system.md)；多图清单与编译读取 [project-packet-and-prompt-compiler.md](project-packet-and-prompt-compiler.md)。

## 一、先判断数量模式

按 [production-pipeline.md](production-pipeline.md) 完成 `R` 规则预检，并记录：

- `countMode=USER_EXPLICIT_5`：用户明确要 5 张。若未指定其它顺序且 `R` 允许，固定采用 G1→G5；不得再把这套结构降为普通候选。
- `countMode=PLATFORM_REQUIRED`：平台/类目规定张数或必备 `GR` 槽位，按当前官方规则执行。
- `countMode=ADAPTIVE`：用户未指定张数，按证据充分度与购买决策复杂度增删，不机械凑五张。

`USER_EXPLICIT_5` 下如遇平台强制槽位、证据不足或品类风险，仍保持五张数量，优先在 G2–G5 中替换最低优先表达，并记录 `defaultRole / resolvedRole / adaptationReason`。可用背标、产品细节、规格、尺度、实收、储运或使用步骤补位；不得用虚假痛点、竞品、资质、价格或 CTA 凑数。

## 二、五张主图默认骨架 `FIVE_CONVERSION_ARC_V1`

每张用户可见策略卡和详细执行稿都只设三个一级项：**画面 / 图内文案 / 设计指引**。默认每张可见文案不超过 5 行；标题、副标题、卖点、价格条件与必要限定都计入。放不下时删弱信息或减弱主张，不能隐藏限定语或缩成不可读小字。

### G1｜图1 封面首图・点击率担当

- **画面**：真实产品居中或占据第一视觉层级，配合能强化材质、口味、使用或品牌气质的氛围背景；加入一个清楚但不遮产品的视觉钩子。
- **图内文案**：标题 + 副标题 + 一个核心卖点 + 必要限定/兜底说明，总计 ≤5 行；首图规则不允许叠字时改为干净产品图。
- **设计指引**：明确 0.5 秒焦点、产品占比、缩略图识别、字体层级和钩子机制；气氛元素不得暗示不存在的成分、功效或赠品。

### G2｜图2 痛点共鸣・用户代入

- **画面**：默认采用“问题场景 vs 产品解决方式”的对照构图，让用户看到具体不便、疑问或使用需求，再看到产品如何参与；不是医学或效果前后图。
- **图内文案**：问句切入 + 中性对照描述 + 已核利益点，总计 ≤5 行。
- **设计指引**：写清情绪从困惑到理解的视线路径。普通食品、受监管品类或无功效证据时，把“痛点”改为购买疑问、使用时刻或选择困惑，禁止症状恐吓、人体器官和效果承诺。

### G3｜图3 差异化卖点・选择区隔

- **画面**：证据充分时使用左/右实拍或 2–3 项数据对照；无同条件竞品证据时，自动改为“本品特征 + 自有证据”的属性板、同品牌 SKU 选择表或适合/不适合说明。
- **图内文案**：差异化标题 + 2–3 个对照/属性点 + 佐证/来源限定，总计 ≤5 行。
- **设计指引**：第一眼看差异结论，第二眼看证据与条件。必须写对象、条件、单位、来源、范围和有效期；不点名贬损、不画虚构旧品/坏品。

### G4｜图4 场景展示・使用价值

- **画面**：默认 2–3 个典型场景并排，三格共享同一视觉系统；产品动作、尺度、接触关系和光向真实。不适合三格时，可有理由地改为单个沉浸场景、尺度图或步骤图。
- **图内文案**：场景标签 + 一句话使用利益 + 关键规格，总计 ≤5 行。
- **设计指引**：说明生活化程度、人物是否必要、场景差异和统一方式；每个场景都必须回答真实购买问题，不能用通用“开心手持”凑格。

### G5｜图5 CTA 行动召唤・购买收口

- **画面**：真实在售产品全家福、包装与配件前后有序，预留撞色行动区；明确实际收到什么。
- **图内文案**：情感价值语 + 真实信任背书 + 有效价格/条件 + CTA，总计 ≤5 行。`R` 或 `D` 不满足时，用规格、实收、储运、服务或购买须知替代价格/CTA。
- **设计指引**：行动区与主体形成清楚撞色但不伪装平台系统按钮；价格、赠品、物流绑定 SKU/地区/期限/条件，证书/报告/品牌背书只用真实 B/E 资产。

## 三、图库方案选择

先列候选，再按以下维度各 0–2 分：

```text
决策重要度：是否回答 P0/P1 买家疑问
证据强度：是否有 F/E 支撑
渠道适配：是否符合 R 与缩略图/移动端任务
信息独占：是否与其他图不重复
视觉表达力：能否一眼看懂且产品清楚
风险扣分：夸张比较、功效暗示、动态字段过期、资质不实（0 至 -4）
```

`ADAPTIVE` 模式优先保留总分高且共同覆盖“身份—理由—选择—使用—收口”的最小集合。`USER_EXPLICIT_5` 不因某个默认表达缺证据就减少张数，而是把该槽位改成安全的 `resolvedRole`；评分用于决定替换内容与优先级。缺证据主张仍标 `PENDING/OMIT`，不能让空泛氛围或虚假信息补位。

## 四、Gate 1：逐图策略卡

每张先只让用户审核以下三项，并附内部绑定：

```text
图 X｜功能角色与购买疑问

画面：
〔产品位置/占比/角度〕+〔具体环境或信息结构〕+〔与卖点一一对应的道具/动作〕+〔第一落点与动线〕。

图内文案：
眉线“……”（可选）
主标题“……”
副标题/标签“……”（可选）
必须精确内容：全部逐字写入豆包 prompt 并在成图中直出；Dxx 同时标明 SKU/地区/期限/条件
文字预算：〔X 组 / X 行；主标题 X 字；真实缩略尺寸检查结果〕

设计指引：
缩略图或详情观看任务；字体层级；产品与背景对比；情绪引导；证据呈现方式；需要避免的误导。末尾内嵌生产绑定：countMode/templateId/defaultRole/resolvedRole/adaptationReason；researchOutlineVersion/approvalVersion（如触发）；SPxx 的 evidenceStatus/selectionStatus；claim/Q/F/E/R/D；状态；compositionFamily / integrationMethod / layoutFingerprint；L/S/T/C 候选、授权与可见文字清单。不得另设第四个用户可见一级项。
```

`USER_EXPLICIT_5` 每张最多 5 行是硬的可读性预算，不要求塞满：必要限定也计入，放不下就减少标题/卖点，不得删限定。其它数量模式按真实图位决定文字预算。无论文字多少，选定内容都由豆包在最终成图中完整直出。

若任务只有一张图，可在 Gate 1 同回合附上该图完整执行稿并一次确认，确认后直接生成；不再增加仅为批量服务的 Gate 2 或 Anchor Checkpoint。

单张无文案、无产品主张的身份概念图可在用户明确缩小范围后不启用详情页 Research Gate；一旦加入成分、工艺、效果、比较、认证、产地、参数或选择理由，仍须先有合格事实与卖点授权。

## 五、Gate 2、锚定检查与逐图生产

策略确认后，把方向锁成 Visual System Contract，并一次完成全部入选图的详细执行稿；每图包含画面、逐块完整排版文案、设计指引和自足 `COMPILED_PROMPT`。STANDARD 在 Gate 2 统一确认整套执行稿，不逐图询问。随后只有存在真实待决变量时才为 G1 做 1–4 个低/中成本构图草案，构图已严格指定时一张即可；如图库同时含棚拍与生活场景，可再做一张差异最大的场景锚。实际锚图使用 Anchor Checkpoint 检查产品像、B/E 完整、层级、质感和文字，过后才批量；FAST 内部用同一标准通过后续跑。

每张最终交付一个生产包：

1. **策略卡定稿**：画面 / 图内文案 / 设计指引；
2. **视觉与资产清单**：Visual System 版本；P/B/E/L/T/S/C 的授权、transferMode、权重、允许/禁止维度；
3. **逻辑 job**：稳定 ID、family、依赖、F/E/R/D、版本、输出与 QA 状态；
4. **画布与版式**：目标槽位、比例、像素、安全区、产品/文字/信息区百分比；
5. **五层源卡与完整中文提示词**：按 [detail-page-prompt-spec.md](detail-page-prompt-spec.md) 编译 GLOBAL/FAMILY/DELTA/VISIBLE_TEXT/ACCEPTANCE，只包含适用字段但最终自足；
6. **文字与成片规格**：豆包完整图文直出、P/B/E 参考保真；每个文字块完整写原文、强制分行、框位、字体类别/气质、字重、相对字号、HEX、对齐、行距、字距、对比、产品关系与 OCR/目视标准；
7. **针对性禁止项**：本张最可能出错的产品、参考泄漏、事实、物理和平台问题；
8. **验收标准**：第一落点、产品保真、B/E、OCR、SKU、事实、缩略图、渠道规则。

## 六、首图与副图的设计质量

### 首图/G1

- 第一落点必须是产品身份或被允许的核心购买理由；“产品居中 70%”只是常见手段，不是硬规定；
- 缩到平台真实列表尺寸后仍能识别 SKU、轮廓和主标题；
- 正面、标签、在售内容与变体必须与商品信息一致；
- 氛围元素只能强化材质、口味、使用或品牌气质，不能盖住产品或暗示不存在的成分/功效；
- 目标渠道禁止促销叠字时，输出干净商品图，不照搬电商海报式大字。

### 信息/证据图

- 一个图只讲一个主要选择理由；证据与主张同屏或紧邻；
- 数据比较写明对象、条件、单位、来源、范围和有效期；缺任何关键项就不用比较图；
- 工厂、实验室、果园、专家、证书、报告只能放真实授权素材，不能用“像真的”AI 画面替代。

### 场景图

- 写清空间、时间、人物动作、产品接触关系与尺度；
- 至少一张需要帮助用户理解大小的图应有可信参照物或标注；
- 不用“开心人物 + 手持产品”这种可套任何商品的空洞场景；
- 人物、道具、液体、食物和产品的光向、接触阴影、遮挡与反射一致。

### 收口图/G5

- 优先回答“收到什么、如何选、有什么限制、如何储运/售后”；
- 价格、折扣、赠品、物流、服务属于 `Dxx`；当前值的 SKU、地区、期限和条件齐全时直接生成在图中，变更时用豆包局部改字或重生该图；
- skill 默认不生成看似可点击的系统/平台控件，不用虚假倒计时或无期限促销；普通行动文案是否可用按目标图位 `R` 判断；
- 末屏免责声明只能汇总，不能补救前面误导。

## 七、图库验收表

```text
规则：张数、槽位、比例、必拍内容、AI 声明符合 Rxx
身份：标题、首图、副图、SKU、详情、直播/投放口径一致
覆盖：每张回答不同购买疑问，没有重复凑数
产品：外形、包装、标签、颜色、数量和在售内容一致
文案：OCR 逐字通过，限定条件邻接，动态字段未过期
证据：所有宣称绑定 F/E；无假资质、假场景、假比较
视觉：缩略图可识别，多图风格统一且构图有变化
物理：材质、光影、尺度、遮挡、液体与接触关系可信
```
