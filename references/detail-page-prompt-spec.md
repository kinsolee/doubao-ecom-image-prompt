# 电商逐屏详细设计执行稿与提示词规范

用于主图、副图和详情页逐屏生产。详情页只有在 [detail-page-design.md](detail-page-design.md) 的设计大纲确认后才进入本阶段；若产品图/零散身份规格曾触发 Research Gate，还必须绑定已获用户确认的卖点信息大纲版本。按大纲屏序一次完成全部逐屏执行稿，最后统一确认，不逐屏打断。目标是把“精致、高级、好看”转换成可直接投喂豆包、设计师可复核的主体关系、网格、镜头、光、材质、空间、文字排版和物理逻辑。生产深度集中在最终 `COMPILED_PROMPT`。参考资产与 Visual System 读取 [visual-reference-and-style-system.md](visual-reference-and-style-system.md)，分层编译与 manifest 读取 [project-packet-and-prompt-compiler.md](project-packet-and-prompt-compiler.md)。

## 一、精致感的可执行定义

一张图至少应有：

- **明确第一落点**：在极短浏览时间内先看见产品身份或本图唯一信息；
- **有意图的尺度差**：主产品、次主体、道具和文字形成大/中/小层级；
- **克制色盘**：中性承载色、品牌色、一个语义点缀色各有职责；
- **可解释的留白**：为视线、文字和呼吸服务，不是“空”；
- **真实的光与材质**：光源方向统一，接触阴影、反射、折射、粗糙度与环境一致；
- **精确排版骨架**：网格、基线、行宽、对齐、字重和卡片系统统一；
- **有语义的细节**：水果、冰块、织物、线条、粒子、人物都必须解释一个真实信息；
- **产品身份稳定**：包装、比例、标签、颜色、数量和 SKU 不能被“艺术化”改写。

下列写法不合格：只有“商业摄影、高级、8K、氛围感”；连续页面只是换背景；用无依据的分子、活性粒子、实验室、英文乱码制造专业感；提示词换个产品名就能原样用于任何商品。

## 二、逐屏详细设计执行卡

每屏追溯到已确认的 `researchOutlineVersion`（如触发）、`outlineVersion` 和准入 `SP-ID/claimId/F/E/R/D`，并保持三个一级项。前两项让人快速评审，第三项包含生产级完整提示词：

```text
主图 Gx｜名称｜countMode｜templateId｜imageSlot｜defaultRole｜resolvedRole｜adaptationReason｜SP/claim/Q/F/E/R/D
或：屏 Dxx｜名称｜moduleId｜moduleInstanceId｜researchOutlineVersion（如触发）｜outlineVersion｜SP/claim/Q/F/E/R/D｜唯一信息

1. 画面：本屏任务；画幅/网格；产品位置/尺度/角度/状态；前中后景；视觉概念与语义道具；镜头；光影；色彩；材质；第一→第二→收尾；与前后屏的变化和边缘衔接。

2. 图内文案：本屏全部 textId。每条使用 compiler canonical schema，写 semanticType、claim/SP/F/E/K/D/R/限定绑定、exactString、强制分行、框位、最大行数、完整字体排版、产品关系与 validation。

3. 设计指引：设计意图与移动端；Visual System/场景族；compositionFamily / integrationMethod / layoutFingerprint；P/B/E/L/T/S/C；事实/证据/规则；针对性禁止项；可观察验收；完整自足 COMPILED_PROMPT。
```

头部元数据不是第四个交付项。用户可见卡片严格只有“画面 / 图内文案 / 设计指引”三个一级项；追溯、状态、适配原因和生产绑定都收进设计指引。

如果“唯一信息”和“第一落点”无法各用一句话说清，回到大纲调整，不开始写长提示词。执行稿不得新增大纲未批准的事实、模块或核心主张；仅改视觉/屏序时升级 outlineVersion，若新增产品卖点或改变 SKU/事实范围，则回退 Research Gate、升级 researchOutlineVersion 并重新确认。所有入选屏一次写完后统一进入 Execution Gate。

## 三、参考图角色与模型能力适配

每个资产同时标语义角色与传输方式：

- `P` 产品身份：锁几何、包装、标签方向、颜色、配件、数量与状态；
- `B` 品牌完整性：logo、字标、二维码、授权图形与监管标识，默认锁定像素；
- `E` 真实证据：原样嵌入或仅分析，不重画、不补编号；
- `L` 宏观版式：只借标题带、区块比例、产品位置、安全区和留白；
- `T` 文字/组件骨架：只借网格、字级、卡片/表格容器和信息密度；
- `S` 风格语言：只借色彩关系、材质气质、光和摄影后期；
- `C` 连续性：已通过的图库/场景族锚点，只锁本族光色、材质、母题与边缘衔接。

传输方式使用 `ANALYSIS_ONLY / MODEL_REFERENCE / LOCKED_LAYER / PROMPT_SPEC`。整条参考详情页和模板拼贴母本固定 ANALYSIS_ONLY；自有/授权的完整单屏裁片才可作 L 像素参考，第三方未知权利原图只转提示词规则或抽象线框。B/E 默认 LOCKED_LAYER；T 只规定字级、对齐、卡片和表格骨架，最终文字仍全部交给豆包直接渲染。

提示词写清“哪张参考控制哪个维度、禁止带入什么、冲突由谁决定”。产品由 P，品牌由 B，证据由 E，主张/限制由 F/R，空间由已确认大纲 + 当前逐屏执行 + L/T，风格由 Visual System + S/C。任何维度都不得反压 P/B/E/F/R。styleWeight 与 layoutWeight 独立。

能力适配：

| 模型能力 | 做法 |
|---|---|
| 仅一张参考图 | 关系编辑优先 `P`；像素锁 P 已是 LOCKED_LAYER 时按任务选择 C/L/S；其余转 `PROMPT_SPEC` |
| 多参考图 | provider 筛选后重新编号；逐张写 assetId、P/L/S/C 角色、允许/禁止维度，条数与实际输入 1:1 |
| 高输入保真/主体保留 | 开启高保真；仍验收包装和文字 |
| 支持遮罩/局部编辑 | 用于道具、背景、非关键阴影、颜色和小范围接触关系；遮罩不保证边界外完全不变 |
| 支持透明背景/合成 | 优先锁真实产品层，让模型生成环境和融合层 |
| 豆包文本渲染 | 标题、副标题、卖点、参数、表格、FAQ、价格与法务全部逐字直出，生成后 OCR/目视校对 |
| 不支持长画幅 | 每屏独立生成后拼接；支持长画幅也优先分屏以便返修和排版 |

实际传入参考示例：

```text
参考图1 [P01｜产品身份]：只锁瓶型、包装、标签方向、颜色和数量，不得按其他参考改版。
参考图2 [C01｜连续性]：只沿用本族光色、材质与母题，不沿用构图，不得改变 P01。
参考图3 [L03｜版式，layoutWeight=65]：只沿用标题位置、区块比例、安全区与留白，不沿用配色、文字、产品、品牌和装饰。
参考图4 [S01｜风格，styleWeight=55]：只沿用色彩关系、光质、材质与后期，不沿用版式、文字、产品和品牌。
```

## 四、生产源卡：16 个检查字段

以下是**源卡字段**，不是要求把每项都堆进提示词。每项标 `P0/P1/P2/N/A`，只编译适用字段；坐标、占比、Hex、角度和焦段另标 `生成引导值 / 验收测量值 / 确定性约束`。

1. **任务与画幅**：渠道、图位、比例、像素、观看端、本图问题；
2. **参考资产**：P/B/E/L/T/S/C、authorization、transferMode、style/layout weight、允许/禁止维度与 provider 点名；
3. **艺术方向**：Visual System 版本、品牌气质、母题、本屏情绪与反面气质；
4. **网格与大区块**：列数、安全区、标题/产品/信息/过渡带百分比；
5. **产品锁**：数量、几何、包装、标签方向、颜色、液位/开合、配件与不可变点；
6. **视觉动线与层级**：第一/第二/收尾落点，尺度差与留白；
7. **前中后景**：每层对象、遮挡、距离、虚化与接触关系；
8. **信息可视化**：元素→事实/意义的一一映射，示意与实证边界；
9. **场景与道具**：空间、时间、表面、人物动作、数量、尺度和语义；
10. **镜头与透视**：机位、俯仰、景别、焦段、景深、焦点、垂直线；
11. **布光与阴影**：主/补/轮廓光、色温、光质、高光、投影方向/长度/软硬；
12. **色彩关系**：Hex/比例、明度/冷暖/色相对比、点缀色用途；
13. **材质与物理**：粗糙度、反射/折射、透光、纹理、凝露、液体/食物/织物状态；
14. **图形与文字**：卡片/图标/线条；每个文字块的完整逐字白名单、强制分行、相对坐标/文本框宽高、最大行数、字体类别/气质、字重、相对字号、HEX、对齐、行距、字距、底色/对比和与产品的对齐/避让/咬合关系；
15. **连续性与版本**：场景族/父锚、上下衔接、P/B/E 锁定参考、豆包完整图文成片、局部改字、job 版本与依赖；
16. **禁止项与验收**：本图最可能失败的具体错误与可观察通过条件。

### 编译优先级

- `P0` 必须放在提示词靠前并在结尾验收再次强化：产品身份、数量、关键关系、白名单、硬性禁项；
- `P1` 负责质感：镜头、光、材质、空间、网格、色彩；
- `P2` 负责气氛：颗粒、轻微空气感、次级装饰；
- 冲突时删除 P2，再删除不必要 P1，绝不牺牲 P0；
- 不用固定 500–1000 字。简单干净图可短，复杂场景可长，标准是无歧义、无矛盾、可验收。

生产深度集中在真正投喂模型的内容，策略摘要/设计意图各用一句即可。多图项目先分为：

1. `GLOBAL_CONSTANTS`：SKU/产品不变量、B/E、Visual System、网格、全局可见文字格式与禁区；
2. `FAMILY_ANCHOR_RULES`：本族环境、光型、镜头、材质、C 与过渡；
3. `IMAGE_DELTA`：本图 SP/claim/Q/F/E/R、构图、场景、动作、文案和局部禁项；
4. `VISIBLE_TEXT_BLOCK`：本屏全部已确认可见文字的逐字字符串和逐块完整排版执行参数；
5. `ACCEPTANCE_CRITERIA`：可观察的 P0 产品、事实、文字和物理标准。

provider adapter 再把五层合成一条自足提示词。GLOBAL/FAMILY 不在每张源卡里手工改写，防止同一规则被逐页同义改写后漂移；但交付给单独生图任务的 COMPILED_PROMPT 必须完整自足。

## 五、版式原型库

按屏数、信息复杂度和场景族选择足够但不过量的版式原型；小套系两三种即可，复杂长页可更多。统一 Visual System，避免每屏同构图。

每屏记录：

- `compositionFamily`：PRODUCT_STAGE / EDITORIAL_CROP / IMMERSIVE_SCENE / DECISION_BOARD / SEQUENCE_PATH / EVIDENCE_COLLAGE / FAMILY_CLOSE；
- `integrationMethod`：留白承字 / 产品咬合 / 物理指向 / 共享背景 / 证据叠合 / 场景连帧；
- `layoutFingerprint`：产品位置、产品尺度、镜头、信息密度、信息拓扑、背景类型。

相邻屏通常至少在版式指纹中变化两项；连续规格表、步骤或同条件比较需要稳定对照时可例外。图文边界可用共享背景、轻微越界或物理指向形成整体感，但参数、营养、FAQ 等信息屏允许清晰卡片边界，不能把“边界柔化”当硬规则。

### A. 编辑式产品主视觉

标题区与产品区形成 25:75、35:65 或错位比例；用一个放大的原料/纹理/结构做次主体。适合身份、核心理由。禁止同时塞表格和多卖点。

### B. 巨物微观静物

原料、液体、材质或结构切面占 40–70%，产品嵌入真实空间层次；微型人物只在明确为创意隐喻、不冒充事实且符合品牌时使用。适合风味、触感、做工。

### C. 沉浸式生活场景

环境约占 55–75%，通过人物动作、视线、桌面动线或光引导到产品；写清时段、空间、姿态、穿着、接触与尺度。适合使用价值，避免空洞手持摆拍。

### D. 编辑式场景矩阵

1+2、2×2 或三联画；共享圆角和边距，每格一个不同决策时刻与短标签。不是所有“场景页”都必须三格。

### E. 证据拼贴

1 个主证据 + 2–3 个辅助真实素材，使用规整时间线、错位卡片或裁切窗。只能使用 `E` 资产；AI 底图不得伪造成真实工厂、果园、实验室或报告。

### F. 对比决策板

左右/上下完全对齐，最多 3–5 个同条件维度。对象、单位、来源、范围和有效期齐全才启用；无证据改为本品属性板或同品牌 SKU 选择板。

### G. 原理/使用路径

3–5 步，单一视觉载体贯穿，编号/箭头/图标同一语言。真实流程绑定 `F/E`；抽象示意显著标“示意”，不画伪科学分子或人体功效路径。

### H. 产品信息编辑板

产品小图 20–35%，信息区 55–70%，定义列表/表格清晰。豆包在同一张成图中完整生成产品、卡片、精确参数、配料、营养与 FAQ 文字，不交付空卡片。

### I. 全家福/购买收口

主品、包装与真实配件前后有序，回答实收、规格、储运或服务；动态价格/赠品/物流在 D 的 SKU、地区、期限与条件确认后直接生成，变化时局部改字；不伪造平台系统按钮。

## 六、完整中文提示词模板

以下是最终 `COMPILED_PROMPT` 模板，按本图删减，不把方括号占位直接交付。项目级常量、场景族规则和本图差量在内部保持分层，最终文本应完整自足；不要让模型依赖“同上”或未随任务传入的聊天记忆。

### 每个文字块的强制展开句式

最终 prompt 中每个 `MODEL_TEXT` 都必须完整展开下列内容，不能把多个字段压进一个模糊 `style`，也不能只把标题写详细、其余写“同上”：

```text
TXT-Dxx-01｜semanticType〔〕｜claimId/SP-ID/F/E/K/D/R/qualifierTextIds〔键均保留；不适用标量 null、集合 []〕｜只渲染批准原文“〔exactString〕”｜强制分行〔renderedLines〕｜位于画布〔region〕，文本框约 x=〔〕%、y=〔〕%、w=〔〕%、h=〔〕%，最多〔〕行｜字体类别〔〕，气质〔〕，字重〔〕，字高约画布高度〔〕%｜颜色 #〔HEX〕｜〔左/中/右〕对齐｜行距〔〕em｜字距〔〕em｜置于〔#HEX/材质〕底色，对比〔高/中〕｜与产品〔对齐/间距/避让/咬合〕｜按 OCR_EXACT + VISUAL 验收。
```

坐标、字号和颜色属于生成引导/验收信息，不属于画面可见文字。有用户/品牌指定且可用的字体时写精确字体名；否则写可识别的字体类别与气质，不用虚构字体名。官方品牌色可标锁定值；视觉估色标设计近似值。逐屏执行稿可引用 Visual System 的母版逻辑，但最终 prompt 仍需为每个文字块写出本屏实际值。

```text
为〔平台/端/图位〕制作〔主图/商品副图/详情页第X屏〕，目标画幅〔比例与像素，以Rxx为准〕。本图只完成一个任务：回答“〔Qxx购买疑问〕”，让用户第一眼看见〔第一落点〕，随后视线移动到〔第二落点〕，最后在〔收尾位置〕读完〔选择信息〕。事实只使用〔Fxx/Kxx/Exx/Rxx〕，〔Uxx〕不得进入画面；已确认 SKU、地区、期限和条件的〔Dxx〕直接写入本图，未确认的 D 不出现。

参考资产与处理路线：〔P/B/E/L/T/S/C assetId、authorization、transferMode〕。P 控制产品身份；B/E 使用真实像素或仅分析，不让模型重画；L/T 只控制空间与信息骨架；S 只控制光色、材质和后期；C 只控制本族连续性。styleWeight=〔值〕，layoutWeight=〔值〕，二者互不代替；任何参考不得覆盖 P/B/E/F/R。

实际模型参考按 provider 适配后共〔N〕张，逐张点名且与输入 1:1：参考图1〔assetId/角色/允许维度/禁止维度〕；参考图2〔……〕。整条详情页/模板母本与 analysis-only 第三方原图不得作为模型参考；只有一张参考能力时按 fidelity route 优先 P，其他规则转为文字。

艺术方向为〔3个有边界的品牌气质〕，核心视觉母题是〔母题〕，本图情绪为〔具体气氛〕；不是〔廉价促销/儿童玩具/伪科技/过度奢华等反面气质〕。使用〔版式原型〕，通过〔尺度差、留白、材质、光或动作〕形成精致感，而不是堆装饰。

画布采用〔网格〕，四周安全区〔百分比〕。标题区位于〔位置/宽高〕，产品区位于〔位置/宽高〕，信息区位于〔位置/宽高〕；最大留白在〔区域〕。产品与标题形成〔对齐/错位/穿插但不遮挡〕关系。视觉层级为〔产品/标题/证据或场景〕，背景细节不得争夺第一落点。

空间分层：前景为〔对象、位置、遮挡比例、焦度〕；中景为〔产品、核心动作、接触关系〕；后景为〔环境、深度、留白与虚化〕。所有物体落在同一空间，接触点有可信压痕/阴影/液体附着；不悬浮、不穿模、不出现尺度矛盾。
```

## 七、不同屏型的加料方式

### 产品/食品静物

必须写清液体透明度和黏度、气泡/凝露尺度、切面湿润度、台面接触、倒液轨迹与重力；冰块和水果不是“清凉新鲜”的万能装饰，只有事实/场景需要才出现。

### 材质/结构微距

写清放大倍率感、焦点平面、材料纹理方向、边缘加工、接缝、公差视觉、粗糙度和反光。结构示意与真实剖面分开标注，不能画出不存在的内部结构。

### 人物场景

写清人物年龄段而非可识别真人、姿态、手部受力、视线、服装材质、产品握持/穿戴关系、比例和场景动线；避免六指、悬空握持、产品缩放异常和无意义微笑摆拍。

### 数据/信息图

豆包在同一张图中完整生成产品、背景、图形骨架、卡片、真实数字、表格、来源和限定文字。所有本品数据先有匹配 `F`；HIGH_RISK 项强制有效且 scope 匹配的 `E/R`，并来自准入 SP/claim；生成后逐项校对。图形必须解释数据，不用伪科学发光球、DNA、人体器官或分子图冒充机制。

### 真实证据屏

生成容器和背景即可，`E` 素材原样放置；不得修正证书文字、补编号、合成不存在的工厂或用 AI 人物冒充研发团队。

## 八、草案、定稿与局部修订

1. 只有存在真实待决变量时，关键锚点才做 1–4 张低/中成本草案；每张只改变一个主变量，如产品偏左/偏右、平视/轻俯拍、浅/深底；构图已严格指定时一张即可；
2. 用户/内部选中后固定 P、构图、相机、色盘和主要物体位置，再提高质量；
3. 每次编辑明确重述保留项：产品、包装、构图、光向、文字区；
4. 任何文字错字、漏字或多字都先用豆包局部改字，明确保留产品、包装、构图、光向与其他文字，编辑后重做包装差异与全图 OCR 检查；
5. 生成历史记录保留稳定 job ID、Visual System/锚点版本、输入 hash、提示词层、参考资产、变化变量、输出和三层 QA；
6. D 字段变化局部改字或重生该 job；单张 L/构图变化只重生该 job；某族锚变化只级联该族；P/SKU 或已批准 SP/claim 变化使所有下游引用失效并重新 QA。恢复项目只续跑缺失或失效任务。

## 九、豆包完整文字规格

对标题、参数、营养、配料、尺寸、FAQ、价格、促销和法务，都输出以下生图规格并逐字写入 prompt：

```text
textId / semanticType：
claimId / sellingPointId / factIds / evidenceIds / knowledgeIds / dynamicIds / ruleIds / qualifierTextIds（键均保留；按 semanticType 强制非空，不适用标量 null、集合 []）：
exactString / renderedLines / forcedLineBreaks：
region / box(x,y,w,h) / width / maxLines：
fontFamilyOrCategory / fontMood / fontWeight / relativeSize：
colorHex / alignment / lineHeight / letterSpacing：
contrastBackground / relationToProduct：
表格附加：行列、每格字符串、单元格对齐、分隔线、单位与来源位置：
限定条件：紧邻哪条主张、对比度与最小可读字级：
动态字段：D-ID、SKU/地区/期限/条件、更新来源：
validation：OCR_EXACT + VISUAL；失败时局部改字并保留其它元素：
```

每个 `MODEL_TEXT` 块都必须填写完整，禁止省略为“沿用标题样式”或把字体参数留给生成后的外部排版。不要把所有小字塞在最后一屏；限制、数据条件和适用范围与对应主张同屏。

## 十、交付前评分

每图 0–2 分，总分至少 18/22 且事实、产品、文字三项必须 2 分。该阈值只表示内部生产完整性，不代表平台审核通过、审美质量或转化提升保证：

| 维度 | 2 分标准 |
|---|---|
| 任务 | 一图一问，第一落点服务该任务 |
| 事实 | 主张绑定已准入 SP/claim/F/E/R，K 未偷换，U/PENDING/禁用 SP 未入图 |
| 产品 | 几何、包装、标签、颜色、数量和 SKU 锁定 |
| 构图 | 区块、尺度、留白、动线可执行 |
| 场景 | 道具、动作和环境都有语义且比例可信 |
| 镜头 | 机位、焦段、焦点和景深明确且合理 |
| 光色 | 主补轮廓、阴影、色盘和对比具体一致 |
| 材质 | 至少两处可观察物理细节，无蜡感/穿模 |
| 版式 | 网格、字级、行宽、组件和安全区清楚 |
| 文字 | 本屏全部已确认文字已直接生成；每个 textId 完整展开原文、分行、框位、字体、字重、字级、颜色、对齐、行距、字距、对比和产品关系；OCR/目视可逐字验收 |
| 连贯 | Visual System/场景族版本一致；L/S/T/C 无内容泄漏；相邻版式指纹有节奏且能承接 |

低分先改源卡或提示词，不用“再加高级感、8K、获奖设计”掩盖结构问题。
